QA gates before expansion

  • Order state modelCreated -> accepted -> cooking -> ready -> picked up -> delivered -> disputed.
  • Failure boundariesRestaurant timeout, courier decline, payment pending, stale location, network loss.
  • Performance targetFast list rendering, cached merchant data, optimistic UI only where reversible.
  • Security boundaryNo private keys, no custodial wallet access, no production credentials in milestone one.

Acceptance checklist

  • Visible proofBuyer can inspect the app slice without giving private access.
  • Bounded scopeMilestone one proves execution quality; full build starts only after acceptance.
  • Stack flexibilityCan implement with React web first, then React Native/Expo if mobile is required.
  • Evidence receiptAll changes ship with a short delivery note, screenshots, and test checklist.

Boundary: this proof slice is not a completed production food-delivery app. It is a low-risk first-milestone preview showing the architecture, UX states, and delivery method MAXIM can execute after escrow acceptance.
